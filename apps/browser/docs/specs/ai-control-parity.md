# AI browser control: capability target and validation

Goal: make Kudium Browser useful for external agents across ordinary web tasks and difficult interactive interfaces, approaching Ego's documented control surface. Any claim of better performance requires comparison on the same machine and workload; it has not yet been established.

Reference reviewed: the installed Ego browser usage guide v2.2.0 (`ego-browser skill`), November 5, 2026. This describes Ego's public API, not independently verified reliability or performance.

## Completed foundation

- Quiet, collapsible, resizable AI panel with shared sidebar motion and a dedicated Preferences page.
- Provider/API-key configuration for the built-in assistant.
- Opt-in authenticated local MCP server using the official SDK, plus a dependency-free stdio bridge.
- Snapshot IDs, pre-approval target receipts, in-place target fingerprint checks, and isolated-world target storage. Old snapshots and controls changed during approval are rejected.
- Nested open shadow-root discovery, automatic target scrolling, and select-option metadata/validation.
- Twenty-seven external tools: list/select/new/close tabs, frame listing, page reading/semantic lookup, navigation/back/forward/reload, click/coordinate-click/type/hover/double-click/press-key, scroll, wheel, drag, wait-until, screenshot.
- Shared signed-in sessions, native mutation approval, password/file-input blocking, cancellation, single-controller exclusion, and connection revocation.
- MCP usage instructions and `kudiumbrowser://guide` resource for external agent workflows.
- Real Electron tests with an official MCP client and no model API key.

## Next implementation milestones

1. **Reliable target selection:** semantic selectors, frame-local pointer coordinates, and semantic target ambiguity errors remain. Out-of-process frame discovery and frame-local command routing are verified. Frame-local reading, typing, clicking, and waits are implemented and verified for same-process cross-origin/nested documents. Snapshot checks, isolated-world reference storage, open shadow roots, and auto scrolling are implemented; explicit snapshot IDs are recommended, with legacy numeric-only calls retained.
2. **Full interaction surface:** coordinate actions, HTML5 DataTransfer drag/drop remain. Native protocol hover/double-click, targeted key/chord input, select values, forward/back/reload with bounded loading checks, and bounded URL/exact-label waits are implemented.
3. **Session ownership and recovery:** external task IDs, protected user-owned tabs, human takeover, popup/dialog receipts, permission handoffs, cancellation of uncommitted navigation, and recovery after navigation/timeouts.
4. **Files and artifacts:** explicit file chooser/upload approval, download tracking and artifact handling, and bounded structured extraction without exposing application credentials.
5. **Efficiency and comparison:** action batches with a final observation, configurable snapshot scope and output budgets, incremental snapshots, operation timings, and controlled benchmarks against the installed Ego version.

## Acceptance criteria

- Reproducible local fixtures cover navigation, login-session continuity, form controls, popup/tab lifecycle, nested frames, shadow DOM, canvas coordinate interactions, upload/download, and human handoff.
- Each mutation is verifiable through page state or screenshot; stale or ambiguous actions fail instead of acting on a different control.
- Stop and access revocation prevent future actions across all transports and close pending native confirmations.
- Existing browser/session tests remain green. Built-in and external modes use the same control engine.
- Optimization reports include cold/steady-state p50 and p95 latency, browser round trips, observation payload sizes, and failure/retry counts. Report tradeoffs rather than asserting unmeasured superiority.

The initial MCP milestone is complete. Broader parity and comparative optimization remain active work.

## Multi-point visual drawing

The shared drag_at tool accepts either the existing x/y/toX/toY endpoints or a complete path of 2–128 points including start/end. Mixed formats, invalid/extra point fields, nonfinite/negative offsets and oversized paths fail validation. The MCP and built-in model schemas expose the same path format. Interpolation preserves every vertex and caps native movement dispatch at 1024 events. Coordinates retain fractional CSS precision.

All requested vertices are resolved against the isolated target and checked for geometry/coverage before pressing; embedded-frame ancestor checks run without pointer dispatch. Each interpolated point rechecks the target before moving. Target movement or changed geometry aborts the path through existing pressed-pointer/session cleanup. Native approval identifies the target, start/end and path vertex count. Existing straight-path behavior is retained. ## Budget pauses and continuation (2026-11-10)

The built-in agent starts with a 60-inference-round execution allowance. Each explicit continuation starts a fresh segment with twice the previous allowance: 120, 240, 480 and so on. A budget pause returns a paused outcome with an explicit incomplete-progress summary and Continue task, retaining the original request, completed tool results, scope, access mode and task identity. The current round allowance is persisted with the checkpoint, including across restart. Continuing can repeat until completion. It requires explicit human continuation and fresh browser observations, and does not replay completed tool calls. A progress prompt near the segment boundary directs the model to finish and verify the requested work rather than suggest unrelated alternatives.

Budget-pause checkpoints remain encrypted and resumable for 24 hours in their chat and across restart when secure storage is available. Ordinary inference-error and human-handoff recovery retains its 15-minute lifetime. Stop clears the paused checkpoint. Switching chats keeps checkpoints isolated to their original chat. A follow-up message in the same chat, provider endpoint and group after a budget pause preserves the tool context and prioritizes the latest request, including status questions. Scheduled task pauses remain owned by the task manager and use its explicit continuation path.
