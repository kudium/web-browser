# TouchBox Personal Data

Personal Data extends the original Password Manager rather than introducing another store. Browser Preferences and Group Settings share the `PersonalData` component and GroupIcon. The old `PasswordManager` export, IPC channel, storage directory, OS credential and login tools remain compatible.

## Records and inheritance

Version 2 encrypted payloads store logins, profiles, payment methods, knowledge notes and documents. Custom fields have values, sensitivity and aliases. Persisted public summaries expose titles, origins, account labels, field counts and source labels, never notes, document text, file contents, source URL queries or field values. The trusted manager renderer additionally receives a bounded preview of non-sensitive values, decrypted for one operation without granting private-value access. OS safeStorage protects metadata where available. AES-256-GCM encrypts the payload with a fresh IV on each atomic write. Existing version 1 payloads migrate on unlock with an owner-only encrypted recovery backup.

Personal Data uses `group:<sessionId>` independently of space, name or cookie profile. Existing tabs in a group share this scope; new groups receive a new session ID. Groups inherit browser-wide records, persist only changed fields as overrides, and can hide/reset inherited records. Deleting a global record removes its overrides. Archiving preserves data. Removing a group offers Cancel, Move local data to browser, or Delete local data; customized inherited records are materialized only when keeping them, and shared originals remain intact.

## Authentication and UI

Add opens the shared editor immediately. On OS-backed vaults, adding/importing and editing non-sensitive information encrypts data without a prompt and immediately discards the temporary key when previously locked. This does not grant access to saved passwords. A master-password fallback must unlock its encryption key to save; its draft remains in the editor. Viewing/editing existing secrets requires authentication. Preferences grants last for that window; leaving the group manager revokes its grants. Lock, suspend, navigation and window destruction revoke access. AI searches can open encrypted permitted facts for a single synchronous operation without granting secret access.

The library and editor use one key/value model without category tabs or an item-type selector. New entries need only a key/value pair; labels, extra values, notes and a website are optional. Existing login, profile, payment and knowledge storage tags remain internal compatibility details. Source labels distinguish global, inherited, customized and group-local data. Group entry points use the same component and scoped target-tab registry. Custom fields support website autocomplete names, IDs, aliases and sensitive masking. Payment fields are always protected. Profiles support inputs, textareas and unambiguous selects; filling never submits.

## Documents

Native file selection accepts PDF, DOCX, TXT and Markdown up to 20 MB per file. PDF.js and Mammoth adapters extract text locally; PDFs include page references. Scanned PDFs without text are rejected with a readable error. Extraction limits are 1,000 PDF pages and two million text characters; the encrypted vault is capped at 90 MB of serialized payload. Originals and extracted text stay encrypted inside the existing vault. Imported documents, existing records and new entries enable AI use automatically; the per-record permission toggle has been removed at the user’s request. Disabling Personal Data still disables the whole service. Approved attachment materializes an owner-only temporary file solely for the existing upload service, then removes it in a finally block. Startup also removes upload files left by a crashed process.

## AI contracts

`search_personal_data(tabId?, query)` searches the target tab's effective group scope and inherited data, never a caller-selected scope. Results contain at most five matches and 4,000 JSON characters, with IDs and source labels. Login matches expose account references only; their secrets and notes are excluded. `read_personal_data(tabId?, recordId, offset?)` returns bounded non-sensitive fields and source passages with nextOffset. Both check global enablement, the derived group scope and any saved website binding on every call. Leaving the website blank makes an entry reusable across websites. Stored document passages are untrusted content, not user instructions.

`fill_personal_data(tabId?, recordId)` fills locally after native approval. Sensitive records additionally require OS authentication or an already unlocked fallback vault. Origin, group scope and lock revision are checked; tool results contain counts only. `list_saved_logins` and `fill_saved_login` delegate to the same records/filling behavior.

`save_personal_data(tabId?, record, destination?, reason)` requires an explicit user request and native human review regardless of general AI access mode. Supported model-provided records are basic profiles and knowledge. Default destination is the target group; browser-wide saving must be explicitly selected. Updates are partial: omitted fields and protected values are preserved, and models cannot replace protected fields. New explicitly sensitive custom values remain masked and excluded from future search.

`capture_personal_form(tabId?, fieldNames, title, destination?, reason)` captures only selected visible controls and presents their values for review. Hidden fields, tokens and one-time codes are excluded. Explicitly selected credentials are saved locally as protected login/payment records with AI use enabled and sensitive filling still requiring approval/authentication; no values return in the receipt. `attach_personal_document(tabId?, recordId, elementId, snapshotId)` requires native approval and reuses the existing observed-file-input upload service.

## Verification

Unit coverage includes legacy migration, encrypted documents/notes, group isolation, partial overrides, hide/reset, move/delete, source metadata, sensitivity aliases, bounded retrieval, partial AI writes, capture filters and profile/payment filling. Native regressions exercise main-frame IPC rejection, lock lifecycle, unprompted creation, locked search, bundled PDF/DOCX extraction and shared UI rendering at normal/narrow widths. A deterministic native AI tool loop verifies scoped search, foreign-record rejection, secret-free provider context, cancelled/reviewed writes, local credential capture and profile filling. Screenshots live in `docs/evidence/personal-data`.

This release remains local: no embeddings, cloud extraction, sync, OCR, passkeys or native application autofill. Windows/Linux still use the existing master-password authentication fallback. Common human field names infer standard autofill aliases (for example Card number → cc-number and Expiry date → cc-exp). Private values remain masked, with authentication before editing saved private data. The native Mac helper remains subject to production signing/notarization checks; automated tests do not authenticate against human OS credentials.
