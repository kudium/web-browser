# Preferences design

## Intent
Preferences should feel like a calm desktop utility: clear labels, restrained color, familiar controls, and predictable spacing. Use Apple’s hierarchy and progressive disclosure as inspiration while retaining Kudium Browser’s existing behavior.

## Window and navigation
- Keep the sidebar and main content independently scrollable. The sidebar uses 34px navigation rows and a quiet selected state.
- Reserve the top 36px for native window dragging, clear of all interactive controls and the macOS traffic lights.
- Use a 220px sidebar, 32px content inset, and a maximum 860px reading width. At smaller window widths reduce the sidebar and allow controls to wrap.
- Show automatic saving status quietly above the page. Errors remain visible and actionable.

## Shared hierarchy
- Page titles: 24px, medium weight, with 20px separation from the first group.
- Setting labels: 14px. Supporting content: 12–13px. Maintain a 16px vertical and 20px horizontal row inset.
- Group related settings in a single rounded surface with subtle dividers. Avoid nesting decorative containers.
- Move explanatory descriptions into an adjacent information button. Its popover supports click, keyboard activation, Escape dismissal, and focus return. Keep meaningful values, save failures, and destructive consequences visible.
- Use neutral secondary buttons and a single emphasized action where needed. Reserve red for destructive actions. Focus outlines must stay visible and unclipped.
- Reuse `GroupPicker` and `GroupIcon` wherever users select a group, including settings that target its shared login profile. Show the same group identity in the selected trigger and results. Include Browser defaults as a clearly labeled option when applicable. Explain when a setting affects other groups sharing a login profile; avoid an unexplained “Scope” label or a separate text-only selector.

## Keyboard shortcuts
- Give the import/export/reset toolbar and search field their own insets.
- Align action names with shortcut bindings and editing controls. Wrap into two lines when space is limited.
- Keep Change explicit. Represent alternate and reset actions with small icons, accessible names, and hover titles. Retain shortcut capture, conflict validation, import review, and unassignment behavior.

## Spaces
- Open space creation in a focused dialog: name, icon, color, Create and Cancel. Disable Create until a nonempty name is entered.
- Present space names in a quiet list and show the selected space’s details and controls. Keep app count, active state, switching, ordering, and deletion easy to identify.
- Open icon selection, emoji entry, and image selection only on demand using the shared `IconPicker` dialog. Keep color customization in its anchored popover. Do not repeat expanded customization palettes in the list.
- Keep rename persistence on blur. Preserve existing icons, custom colors, apps, groups, and confirmation before deletion.

## Verification
Check narrow and standard window sizes, light and dark appearance, focused fields, help and picker popovers, keyboard navigation, shortcut capture, and Space creation/rename/reordering. Native dragging requires verification in Electron because browser previews do not implement app regions.

### Required review for every UI change
These requirements apply throughout Kudium Browser, including Preferences, group settings, dialogs, tabs, and menus. A UI change is complete only after reviewing the actual changed interaction in the rendered app. TypeScript, lint, and functional tests do not establish visual correctness.

- Exercise every affected state: collapsed and expanded, hover, keyboard focus, selected, disabled, loading, empty, and error where applicable. Open every changed disclosure, menu, and popover; reviewing its closed state is insufficient.
- Inspect standard and narrow window sizes in both light and dark appearance. Check the dialog and its portaled controls as well as the surrounding page. Use disposable fixture data for private-information surfaces.
- Check matching input font families, sizes, line heights, heights, padding, and baselines. Reuse shared controls instead of introducing native inputs with different styling. Multiline fields must align with neighboring controls in their initial state.
- Check visible clearance around toggles, labels, helper text, inputs, and actions in every state. Expanded options must preserve the field/action spacing contract. For native disclosure elements such as `details`, put related controls in an explicit content wrapper and verify that its gaps apply in the browser.
- Check focus outlines, clipping, wrapping, scrolling, and access to footer actions at narrow sizes. Inspect screenshots of the affected states from Electron; browser previews can supplement checks but cannot verify native behavior.
- When a visual defect is found, add a focused layout check when it can reliably detect the defect, such as matching input typography or minimum clearance between controls. Avoid duplicating implementation details in tests; retain visual inspection for qualities automated checks cannot establish.
- Before reporting completion, state which states and sizes were actually inspected and disclose any verification that could not be performed. Never imply that an unreviewed state passed.

## Container spacing contract
A page may contain several groups, status surfaces, and notes. The page wrapper provides a 16px vertical gap; each bordered group contains padded setting rows. Status callouts sit between groups, not flush against an enclosing border. If a callout is nested in a group, it receives 16px vertical and 20px horizontal clearance. Group headings and notes align with row text using the same 20px inset.

List pages own their layout instead of inheriting an extra decorative outer card. Groups, Spaces, and Archive use consistent list and empty-state insets. Field/action stacks keep 12px gaps, and narrow layouts wrap controls before they overflow. Ghost buttons and icon buttons have no negative margins inside Preferences: their visual bounds must respect the gaps between controls. Preserve space around focus outlines, notices, retry controls, and dialog actions. Save failures belong inside the active editor.

Report async callbacks that exceed ten seconds, limit excessive logging, and pause rapid page-control loops. Unsaved or failed saves must not become active hooks.
